## 为什么需要动画

静态的 3D 场景虽然酷，但你肯定想让物体动起来 —— 方块旋转、飞船飞行、相机移动。在 Three.js（以及大多数 JavaScript 动画框架）中，动画的核心原理和**定格动画**完全一样：

1. 把物体稍微移动一点
2. 拍一张"照片"（即渲染一帧画面）
3. 再把物体移动一点
4. 再拍一张"照片"
5. 重复这个过程，每秒大约 60 次

这就是所谓的 **FPS（Frames Per Second，每秒帧数）**。大多数电脑屏幕以 **60fps** 运行，游戏电脑可能达到 120fps 甚至 144fps。我们的目标就是在这每一帧里更新物体状态并重新渲染。<LessonPreview lesson="05-animations" />

## requestAnimationFrame 详解

### 它是什么？

`window.requestAnimationFrame` 是浏览器提供的一个原生 API。它的核心作用是：**在浏览器下一次重绘之前，调用你指定的回调函数**。

:::important 关键认知
`requestAnimationFrame` 的最初设计目的并不是"做动画"，而是"在下一帧触发一次函数调用"。我们通过在回调函数内部再次调用 `requestAnimationFrame` 来实现循环。
:::

### 基本用法

```js
const tick = () => {
  // 1. 更新物体（移动、旋转、缩放等）
  mesh.rotation.y += 0.01;

  // 2. 渲染场景
  renderer.render(scene, camera);

  // 3. 请求下一帧再次调用这个函数
  window.requestAnimationFrame(tick);
};

// 必须手动调用一次来启动循环！
tick();
```

:::caution[常见陷阱]
不要忘记在定义函数后**手动调用一次** `tick()`。如果不调用，函数永远不会被执行，屏幕上什么都不会发生。这个错误非常常见，即使是有经验的开发者也会偶尔忘记。
:::

### 为什么不使用 setInterval？

你可能会想：用 `setInterval` 也能实现循环，为什么要用 `requestAnimationFrame`？

```js
// ❌ 不推荐的方式
setInterval(() => {
  mesh.rotation.y += 0.01;
  renderer.render(scene, camera);
}, 1000 / 60); // 约 16.67ms
```

`requestAnimationFrame` 相比 `setInterval` 有以下重要优势：

1. **与屏幕刷新率同步**：`requestAnimationFrame` 会在浏览器的每次重绘之前执行，与显示器的刷新率完美同步。而 `setInterval` 无法保证这一点，可能导致画面撕裂。

2. **性能优化**：当用户切换到其他标签页时，浏览器会自动暂停 `requestAnimationFrame` 的执行，节省 CPU/GPU 资源。`setInterval` 则会持续运行，浪费性能。

3. **更精确的时机**：浏览器会在最佳时机调用回调，通常在样式计算和布局之后、实际绘制之前。

4. **自动适应高刷新率屏幕**：在 120Hz 或 144Hz 的显示器上，`requestAnimationFrame` 会以更高的频率调用，动画更加流畅。

参考文档：[MDN - window.requestAnimationFrame](https://developer.mozilla.org/zh-CN/docs/Web/API/Window/requestAnimationFrame)

### 回调函数命名

回调函数的名字没有硬性要求，常见的命名方式有：

- `tick` — 最常见的命名，像时钟的"滴答"声，每帧执行一次
- `loop` — 强调这是一个循环
- `animate` — 强调动画的目的
- `gameLoop` — 常用于游戏开发

本教程统一使用 `tick`。

## 帧率独立性（核心概念）

### 问题：为什么固定增量的动画不稳定？

假设你写了一个简单的旋转动画：

```js
mesh.rotation.y += 0.01;
```

这段代码的意思是：**每一帧让物体旋转 0.01 弧度**。

- 在 **60fps** 的电脑上：一秒旋转 `60 x 0.01 = 0.6` 弧度
- 在 **120fps** 的电脑上：一秒旋转 `120 x 0.01 = 1.2` 弧度
- 在 **30fps** 的电脑上：一秒旋转 `30 x 0.01 = 0.3` 弧度

同样的代码，在不同设备上产生了完全不同的旋转速度！这就是**帧率依赖**的问题。

:::danger 核心原则
**动画速度必须与帧率无关。** 无论用户使用什么设备，动画的表现都应该一致。
:::

### 解决方案：基于时间的动画

要解决这个问题，我们需要使用**真实时间**来驱动动画，而不是依赖"每帧执行一次"的假设。

## 使用 Date.now() 手动计算时间差

在 Three.js 提供便捷工具之前，我们可以使用原生 JavaScript 的 `Date.now()` 来实现帧率独立的动画。

`Date.now()` 返回的是一个**时间戳** —— 从 1970 年 1 月 1 日 00:00:00 UTC 到现在的毫秒数（即 Unix 时间）。

```js
let time = Date.now(); // 记录起始时间

const tick = () => {
  // 获取当前时间
  const currentTime = Date.now();

  // 计算两帧之间的时间差（毫秒 → 秒）
  const deltaTime = (currentTime - time) / 1000;

  // 更新时间记录，为下一帧做准备
  time = currentTime;

  // 使用 deltaTime 驱动动画
  mesh.rotation.y += 1 * deltaTime; // 每秒旋转 1 弧度

  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};

tick();
```

关键步骤解析：

1. **记录上一次的时间**：用变量 `time` 保存上一次 tick 执行时的时间
2. **获取当前时间**：用 `Date.now()` 获取此刻的时间
3. **计算时间差**：`currentTime - time` 得到两帧之间的毫秒差，除以 1000 转换为秒
4. **更新时间记录**：`time = currentTime`，为下一帧的计算做准备
5. **用时间差驱动动画**：乘以 deltaTime 后，无论帧率如何，动画速度都一样

## Three.js Timer 工具类

Three.js 提供了一个内置的 `THREE.Timer` 类，帮我们封装了上述的时间计算逻辑，使用起来更加简洁。

### 创建 Timer 实例

```js
const timer = new THREE.Timer();
```

Timer 在实例化时会自动记录当前时间作为起点。

:::note[关于 Clock]
Three.js 早期版本使用 `THREE.Clock` 类，但从 v0.184 起已弃用，推荐使用 `THREE.Timer` 作为替代。
:::

### update() + getElapsed() — 获取经过时间

`getElapsed()` 返回从 Timer 创建到现在的**总秒数**。与旧版 Clock 不同，你必须在每帧**先调用 `timer.update()`**，然后再获取时间值。

```js
const timer = new THREE.Timer();

const tick = () => {
  timer.update();
  const elapsedTime = timer.getElapsed();
  // elapsedTime 从 0 开始，每秒增加 1

  // 示例：每秒旋转一整圈
  mesh.rotation.y = elapsedTime * Math.PI * 2;

  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};
tick();
```

:::tip[Math.PI * 2 的含义]
在数学中，一个完整的圆周是 `2 * PI`弧度（约 6.28 弧度）。所以`elapsedTime * Math.PI * 2` 表示：随着时间每过 1 秒，角度增加一个完整的圆周，即每秒转一圈。
:::

**注意**：这里用的是 `=` 赋值，不是 `+=` 增量。我们直接用时间值设置旋转角度，而不是在上一帧的基础上增加。这样动画天然就是帧率独立的。

### getDelta() — 获取帧间时间差

`getDelta()` 返回**上一帧到这一帧之间的时间差**（秒）。同样需要先调用 `timer.update()`。

```js
const timer = new THREE.Timer();

const tick = () => {
  timer.update();
  const deltaTime = timer.getDelta();
  // deltaTime 通常是 0.016 左右（60fps 下约 16.67ms）

  mesh.rotation.y += 1 * deltaTime;

  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};
tick();
```

:::tip[优势：getDelta() 和 getElapsed() 不再冲突]
与旧版 Clock 不同，Timer 的 `getDelta()` 和 `getElapsed()` **可以在同一帧内安全地同时使用**，因为 `update()` 已经统一更新了内部状态。
:::

参考文档：[Three.js - Timer](https://threejs.org/docs/#api/en/core/Timer)

### getElapsed() vs getDelta() 对比

| 特性          | `getElapsed()`                      | `getDelta()`                           |
| ------------- | ------------------------------------ | -------------------------------------- |
| 返回值        | 从 Timer 启动到现在的总秒数         | 上一帧到这一帧的时间差（秒）           |
| 使用方式      | 直接赋值 `rotation.y = time * speed` | 增量更新 `rotation.y += speed * delta` |
| 典型场景      | 持续循环动画（旋转、摆动）           | 基于增量的物理模拟                     |
| 60fps 下的值  | 持续递增 0, 1, 2, 3...               | 约等于 0.0167                          |
| 120fps 下的值 | 持续递增 0, 0.5, 1, 1.5...           | 约等于 0.0083                          |

## 使用三角函数创建动画

通过结合 `getElapsed()` 和数学三角函数，我们可以创建各种丰富的动画效果。

### 上下弹跳（正弦函数）

```js
timer.update();
const elapsedTime = timer.getElapsed();
mesh.position.y = Math.sin(elapsedTime);
```

`Math.sin()` 返回值在 -1 到 1 之间循环变化。随着时间推移，物体会在 y = -1 到 y = 1 之间上下弹跳。

:::note[回顾：三角函数基础]

- `Math.sin(x)` — 返回 -1 到 1 之间的值，从 0 开始
- `Math.cos(x)` — 返回 -1 到 1 之间的值，从 1 开始
- `Math.PI` — 约 3.14159，半圆的弧度
- `Math.PI * 2` — 约 6.28318，完整圆周的弧度

你可以用 Google 搜索 "sine wave" 来查看正弦波的图像，帮助理解它的变化规律。
:::

### 圆形运动轨迹

```js
timer.update();
const elapsedTime = timer.getElapsed();
mesh.position.x = Math.sin(elapsedTime);
mesh.position.z = Math.cos(elapsedTime);
```

**原理**：当你把 `Math.sin()` 的值赋给 x 轴，把 `Math.cos()` 的值赋给 z 轴（使用相同的角度值），物体就会沿着一个圆形轨迹运动。这正是极坐标到直角坐标的转换公式。

### 呼吸缩放效果

```js
timer.update();
const elapsedTime = timer.getElapsed();
const scale = 1 + Math.sin(elapsedTime * 2) * 0.2;
mesh.scale.set(scale, scale, scale);
```

物体的大小会在 0.8 到 1.2 之间以"呼吸"的节奏变化。

### 组合动画效果

你可以同时应用多种变换来创造复杂效果：

```js
const tick = () => {
  timer.update();
  const elapsedTime = timer.getElapsed();

  // 旋转
  mesh.rotation.y = elapsedTime * 0.5;
  mesh.rotation.x = elapsedTime * 0.3;

  // 上下弹跳
  mesh.position.y = Math.sin(elapsedTime) * 0.5;

  // 呼吸缩放
  const scale = 1 + Math.sin(elapsedTime * 2) * 0.1;
  mesh.scale.set(scale, scale, scale);

  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};
tick();
```

### 动画摄像机

你不仅可以动画物体，还可以动画摄像机本身：

```js
const tick = () => {
  timer.update();
  const elapsedTime = timer.getElapsed();

  // 让摄像机绕着原点做圆形运动
  camera.position.x = Math.sin(elapsedTime) * 3;
  camera.position.z = Math.cos(elapsedTime) * 3;

  // 让摄像机始终看向场景中心
  camera.lookAt(mesh.position);

  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};
tick();
```

`camera.lookAt()` 接收一个 `THREE.Vector3` 参数，会让摄像机转向看向指定的位置。这里我们让摄像机始终盯着方块，产生一种"环绕观察"的效果。

:::tip
`lookAt()` 必须在**更新完摄像机位置之后**调用。如果顺序反了，摄像机会先转向目标位置，然后才移动到新位置，导致方向不正确。
:::

## 缓动函数（Easing Functions）概念

在真实世界中，物体很少匀速运动。球掉到地上会先加速后减速，弹簧会来回弹跳，开门时我们会先快后慢。**缓动函数**就是用来模拟这类非匀速运动的数学函数。

常见的缓动类型：

| 名称        | 效果                   | 应用场景               |
| ----------- | ---------------------- | ---------------------- |
| Linear      | 匀速运动               | 很少使用，看起来不自然 |
| Ease In     | 开始慢，结束快         | 物体加速飞出           |
| Ease Out    | 开始快，结束慢         | 物体减速停下           |
| Ease In Out | 开始慢，中间快，结束慢 | 大多数 UI 动画         |
| Bounce      | 弹跳效果               | 球体落地               |
| Elastic     | 弹性效果               | 弹簧运动               |

在使用 `requestAnimationFrame` + 数学函数时，你可以自己实现简单的缓动：

```js
// 简单的 easeInOut 缓动（使用 sin 函数）
const progress = (Math.sin(elapsedTime * Math.PI - Math.PI / 2) + 1) / 2;
mesh.position.x = progress * 5; // 从 0 移动到 5
```

但如果需要更复杂的缓动效果，推荐使用 GSAP 等动画库。

## GSAP 动画库

### 为什么要用动画库？

手写基于 `requestAnimationFrame` 的动画虽然灵活，但当你需要以下功能时会变得复杂：

- **精确的时序控制**（延迟、持续时间、回调）
- **复杂的缓动函数**（弹性、弹跳等）
- **时间线**（多个动画按顺序或并行执行）
- **动画链**（一个动画结束后触发下一个）

这时，使用一个专业的动画库会大大提升效率。其中最著名的就是 **GSAP（GreenSock Animation Platform）**。

### 安装 GSAP

```bash
npm install gsap
```

:::tip[关于版本号]
课程中使用了 `gsap@3.5.1`。对于你自己的项目，直接安装最新版本即可：`npm install gsap`。版本更新通常会带来更好的性能和更多功能。
:::

### 基本用法：gsap.to()

`gsap.to()` 是 GSAP 最核心的方法，用于将属性从当前值**动画到目标值**。

```js
import gsap from "gsap";

// 语法：gsap.to(目标对象, { 属性: 目标值, ...配置 })
gsap.to(mesh.position, {
  x: 2, // 将 position.x 从当前值动画到 2
  duration: 1, // 动画持续 1 秒
  delay: 1, // 等待 1 秒后开始
});
```

### 让物体回到原位

```js
gsap.to(mesh.position, {
  x: 2,
  duration: 1,
  delay: 1,
});

gsap.to(mesh.position, {
  x: 0, // 回到原位
  duration: 1,
  delay: 3, // 3 秒后开始
});
```

### GSAP 的工作原理

GSAP 在库内部**独立管理自己的 `requestAnimationFrame` 循环**。这意味着：

1. 你**不需要**告诉 GSAP 何时更新 —— 它会自动处理
2. 但你**仍然需要**自己的 `requestAnimationFrame` 循环来持续渲染场景
3. GSAP 只负责更新属性值，渲染仍由你控制

```js
import gsap from "gsap";

// GSAP 动画（库内部有自己的 tick）
gsap.to(mesh.position, { x: 2, duration: 1, delay: 1 });

// 你自己的渲染循环（必须保留！）
const tick = () => {
  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
};
tick();
```

:::caution[常见错误]
即使使用了 GSAP 控制动画，你**仍然必须保持 `requestAnimationFrame` 渲染循环**。GSAP 只是在后台修改属性的数值，但如果你不持续调用 `renderer.render()`，画面不会更新。
:::

### GSAP 的更多能力（后续课程会用到）

GSAP 功能非常强大，以下是一些你会经常用到的特性：

```js
// 缓动函数
gsap.to(mesh.position, {
  x: 2,
  duration: 1,
  ease: "elastic.out(1, 0.3)", // 弹性效果
});

// 时间线（Timeline）- 多个动画按顺序执行
const tl = gsap.timeline();
tl.to(mesh.position, { x: 2, duration: 1 })
  .to(mesh.position, { y: 2, duration: 1 })
  .to(mesh.rotation, { y: Math.PI, duration: 1 });

// 回调函数
gsap.to(mesh.position, {
  x: 2,
  duration: 1,
  onComplete: () => {
    console.log("动画完成了！");
  },
});
```

参考文档：[GSAP 官方文档](https://gsap.com/docs/v3/)

## 选择合适的动画方案

没有绝对正确的选择，取决于你的项目需求：

| 方案                                    | 适用场景                         | 优点                    | 缺点                  |
| --------------------------------------- | -------------------------------- | ----------------------- | --------------------- |
| `requestAnimationFrame` + 数学函数      | 持续循环动画（旋转、摆动、跟随） | 无额外依赖，性能好      | 复杂时序难以管理      |
| `requestAnimationFrame` + `THREE.Timer` | 同上（推荐方式）                 | 帧率独立，Three.js 内置 | —                    |
| GSAP                                    | 一次性过渡动画、复杂时序         | 功能强大，API 简洁      | 增加包体积            |

经验法则：

- 如果只需要简单的 `Math.sin()` / `Math.cos()` 循环动画 → 直接用 Timer
- 如果需要复杂的过渡、缓动、时间线 → 用 GSAP
- 很多时候两者可以结合使用：GSAP 处理一次性过渡，Timer 处理持续循环

## 完整代码示例

```js
import * as THREE from "three";
import gsap from "gsap";

// Canvas
const canvas = document.querySelector("canvas.webgl");

// Scene
const scene = new THREE.Scene();

// Object
const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshBasicMaterial({ color: 0xff0000 });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

// Sizes
const sizes = { width: 800, height: 600 };

// Camera
const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height);
camera.position.z = 3;
scene.add(camera);

// Renderer
const renderer = new THREE.WebGLRenderer({ canvas: canvas });
renderer.setSize(sizes.width, sizes.height);

// Timer
const timer = new THREE.Timer();

// GSAP animation
gsap.to(mesh.position, { duration: 1, delay: 1, x: 2 });

// Animation loop
const tick = () => {
  timer.update();
  const elapsedTime = timer.getElapsed();

  // Update controls (if any)
  // controls.update()

  // Render
  renderer.render(scene, camera);

  // Call tick again on the next frame
  window.requestAnimationFrame(tick);
};

tick();
```
