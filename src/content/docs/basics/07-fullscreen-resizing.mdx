## 为什么全屏很重要？

目前，我们的画布使用的是固定尺寸 `800 x 600`。对于学习和测试来说这没问题，但在实际项目中，我们通常希望 3D 场景占据整个屏幕。

想象一下你去电影院看电影：如果电影只占屏幕中间一小块，四周都是黑色或者网页的白色背景，那种感觉完全不沉浸。3D 体验也是一样 —— 当画布铺满整个视口时，用户才能完全"进入"你的 3D 世界。

当然，不是所有场景都必须全屏。你可以把 3D 画布放在网页的某个区域（比如一个产品展示卡片），然后让用户滚动来查看。这完全取决于你的需求。但在后续课程中，我们将追求**非常沉浸式的体验**，所以全屏适配是基础。

## 视口（Viewport）的概念

在开始之前，我们需要明确几个概念的区别：

| 术语                 | 含义                                                               |
| -------------------- | ------------------------------------------------------------------ |
| **视口（Viewport）** | 浏览器窗口中实际显示网页内容的区域，不包括地址栏、书签栏、标签栏等 |
| **窗口（Window）**   | 整个浏览器窗口，包括工具栏、状态栏等                               |
| **屏幕（Screen）**   | 物理显示器的整个显示区域                                           |

我们使用 `window.innerWidth` 和 `window.innerHeight` 来获取视口的尺寸，而非屏幕或窗口。在 JavaScript 中，它恰好是挂在 `window` 对象上，但返回的是视口的宽度和高度。

## 步骤一：让画布占满视口

### 更新尺寸变量

之前我们使用的是硬编码的尺寸：

```js
const sizes = {
  width: 800,
  height: 600,
};
```

现在，将其替换为视口的实际大小：

```js
const sizes = {
  width: window.innerWidth,
  height: window.innerHeight,
};
```

`window.innerWidth` 返回视口的宽度（单位：像素），`window.innerHeight` 返回视口的高度。保存后，画布会立即扩展到视口大小。

### 解决默认样式问题

保存后你可能会发现两个问题：

1. **顶部和左侧有空白** —— 浏览器给 `body` 等元素默认添加了 `margin`
2. **出现了滚动条** —— 画布的高度可能超出了视口高度，导致页面可以滚动

这些空白和滚动条会破坏沉浸感。问题出在浏览器的**默认样式**上 —— 浏览器会给 `<body>` 和许多元素（如 `<h1>`、`<p>` 等）添加默认的 `margin` 和 `padding`。

## 步骤二：CSS 全屏配置

我们需要通过 CSS 来消除这些默认样式。以下是完整的 CSS 配置及逐行解释：

```css
* {
  margin: 0;
  padding: 0;
}

html,
body {
  overflow: hidden;
}

.webgl {
  position: fixed;
  top: 0;
  left: 0;
  outline: none;
}
```

### 逐条解释

#### 1. `* { margin: 0; padding: 0; }` — 全局重置

```css
* {
  margin: 0;
  padding: 0;
}
```

- **`*`（通配选择器）** — 选中页面上的**每一个 HTML 元素**
- **`margin: 0`** — 移除所有元素的外边距。外边距是元素外部的空间，浏览器的默认样式会给 `body` 添加约 8px 的 `margin`，这就是你在顶部和左侧看到的空白
- **`padding: 0`** — 移除所有元素的内边距。内边距是元素边框和内容之间的空间

:::tip
这叫做 **CSS Reset（样式重置）**。很多项目都会在样式表开头写这段代码，来抹平不同浏览器之间的默认样式差异。它是前端开发的基本操作。
:::

#### 2. `html, body { overflow: hidden; }` — 禁止滚动

```css
html,
body {
  overflow: hidden;
}
```

- **`overflow: hidden`** — 隐藏超出容器边界的内容。当内容超出视口时，不会显示滚动条，也不会允许用户滚动

:::caution[为什么需要禁止滚动？]

即使我们已经让画布铺满整个视口，在某些设备上（特别是 MacBook 的触控板），用户仍然可以通过触控板或鼠标滚轮"过度滚动"，导致页面出现弹性的上下抖动效果。`overflow: hidden` 可以彻底禁止这种行为，确保页面无法滚动。

如果你的网页上还有其他内容需要滚动（比如文字介绍、导航栏等），你可能需要更精细的布局策略。但在纯 3D 沉浸式体验中，禁止滚动是标准做法。
:::

#### 3. `.webgl` 类的定位样式

```css
.webgl {
  position: fixed;
  top: 0;
  left: 0;
  outline: none;
}
```

这段 CSS 作用于我们给画布元素添加的 `webgl` 类名。

- **`position: fixed`** — 将元素从正常的文档流中取出，**固定在视口中**。无论用户怎么滚动（虽然我们已经禁止了滚动），这个元素都不会移动。与之相比，`position: absolute` 是相对于最近的定位祖先元素定位，如果祖先元素没有设置 `position`，效果和 `fixed` 类似。课程中选择 `fixed` 是因为它更强、更可靠

- **`top: 0; left: 0`** — 将画布的左上角定位到视口的左上角（坐标 0, 0）。这样画布就会从视口的最左上角开始铺展

- **`outline: none`** — 移除元素被聚焦时的**蓝色轮廓**。当用户在画布上按下鼠标并拖拽时，某些浏览器（如 Chrome）会在画布周围显示一个蓝色的边框轮廓。这在 3D 体验中看起来很不专业，所以用 `outline: none` 去掉它

:::note[`position: fixed` vs `position: absolute`]
两者都可以让画布覆盖整个视口，但 `position: fixed` 是相对于**视口**定位，`position: absolute` 是相对于**最近的定位祖先元素**定位。如果你的 3D 画布是页面中唯一的内容，两者效果相同。但如果页面中还有其他内容（如覆盖在 3D 上的 UI 面板），使用 `fixed` 能确保画布始终覆盖视口，不受其他元素布局的影响。
:::

### 效果

应用以上 CSS 后，你的 3D 画布将：

- 铺满整个视口，没有空白
- 不会出现滚动条
- 拖拽时不会出现蓝色轮廓

## 步骤三：处理窗口大小变化（Resize）

到目前为止，画布在页面加载时确实铺满了视口。但还有一个问题：**如果用户调整了浏览器窗口的大小怎么办？**

试试看 —— 拖动浏览器窗口的边缘来改变大小。你会发现：

- 画布的大小**没有跟随变化**
- 3D 场景的内容可能会被拉伸、变形，甚至看不到

这是因为我们只在页面加载时设置了一次尺寸，当窗口大小改变后，Three.js 并不知道这件事。

### 监听 resize 事件

我们需要监听浏览器的 `resize` 事件。这是一个原生的 JavaScript API，和 Three.js 无关：

```js
window.addEventListener("resize", () => {
  console.log("窗口大小已改变");
});
```

当用户调整浏览器窗口时，回调函数会被触发。你可以在控制台中看到日志输出。

### 在回调中做什么？

当窗口大小改变时，我们需要更新**三个东西**：

#### 1. 更新尺寸变量

```js
sizes.width = window.innerWidth;
sizes.height = window.innerHeight;
```

重新获取最新的视口尺寸。虽然更新这个对象本身不会改变任何渲染，但后面的代码需要用到最新的宽高值。

#### 2. 更新相机的宽高比（Aspect Ratio）

```js
camera.aspect = sizes.width / sizes.height;
```

还记得我们在创建透视相机时传入的第二个参数吗？就是宽高比 `sizes.width / sizes.height`。这个值决定了 3D 场景在屏幕上的**投影比例**。

当窗口大小改变时（比如从正方形变成宽屏），宽高比也会随之改变。如果不更新它，物体看起来就会被拉伸或压扁 —— 就像一张照片被不均匀地拉大了一样。

#### 3. 调用 `updateProjectionMatrix()`

```js
camera.updateProjectionMatrix();
```

**这是很多人容易忘记的一步！** 仅仅修改 `camera.aspect` 的值是不够的。

:::note[为什么需要调用 updateProjectionMatrix()？]

相机的内部使用一个叫做**投影矩阵（Projection Matrix）**的数学矩阵来计算 3D 物体如何投影到 2D 屏幕上。这个矩阵是在相机创建时根据 FOV、宽高比、近/远裁剪面计算出来的。

当你修改了 `camera.aspect` 之后，这个矩阵已经过时了 —— 它还在使用旧的宽高比。你必须调用 `camera.updateProjectionMatrix()` 来告诉 Three.js："我修改了相机参数，请重新计算投影矩阵。"

好消息是，你不需要自己处理矩阵计算（那是数学家和 GPU 的事），只需要调用这个方法，Three.js 会自动完成所有的数学运算。

如果只更新 `aspect` 而不调用 `updateProjectionMatrix()`，你会发现调整窗口后画面会有奇怪的拉伸效果。
:::

参考文档：[Three.js - PerspectiveCamera](https://threejs.org/docs/#api/en/cameras/PerspectiveCamera)（查看 `updateProjectionMatrix` 方法）

#### 4. 更新渲染器尺寸

```js
renderer.setSize(sizes.width, sizes.height);
```

这一步会同时做两件事：

1. **更新 WebGL 画布的 CSS 尺寸和渲染分辨率** —— 让画布跟随新的窗口大小
2. **更新内部渲染缓冲区** —— 告诉 GPU 按新的尺寸进行渲染

如果不调用 `renderer.setSize()`，即使相机已经正确更新，画布本身的物理大小和渲染分辨率仍然是旧的，所以你看到的场景要么被裁切，要么被拉伸。

:::tip[渲染器 setSize 的两个参数]
`renderer.setSize(width, height)` 接收两个参数。第三个可选参数 `updateStyle`（默认为 `true`）控制是否同时更新 CSS 样式。通常保持默认值即可。
:::

### 完整的 resize 处理代码

```js
window.addEventListener("resize", () => {
  // 更新尺寸
  sizes.width = window.innerWidth;
  sizes.height = window.innerHeight;

  // 更新相机
  camera.aspect = sizes.width / sizes.height;
  camera.updateProjectionMatrix();

  // 更新渲染器
  renderer.setSize(sizes.width, sizes.height);
});
```

### 执行顺序

注意这三个步骤的执行顺序很重要：

1. **先更新尺寸变量**（因为后面两步要用到新值）
2. **再更新相机**（更新宽高比 + 重新计算投影矩阵）
3. **最后更新渲染器**（根据新的画布大小渲染）

如果你颠倒了顺序（比如先更新渲染器再更新相机），可能会看到一瞬间的画面闪烁或拉伸，因为渲染器在渲染时相机还没准备好。

## 步骤四：处理设备像素比（Pixel Ratio）

### 什么是 devicePixelRatio？

如果你使用的是 **Retina 屏幕**（如 MacBook Pro、高端手机），你可能会注意到 3D 画面看起来有些**模糊**，或者在几何体的边缘能看到**锯齿状的阶梯效果**。

这和**设备像素比（devicePixelRatio，简称 DPR）**有关。

:::note[用生活来理解像素比]

想象你的屏幕是一面由很多小方格（像素）拼成的墙：

- **普通屏幕（DPR = 1）** — 每个软件像素对应 1 个物理像素。方格比较大，离近了能看到格子
- **Retina 屏幕（DPR = 2）** — 每个软件像素对应 4 个物理像素（2x2）。屏幕用 4 个更小的物理像素来显示 1 个软件像素，看起来更精细
- **高端手机（DPR = 3 甚至更高）** — 每个软件像素对应 9 个物理像素（3x3）或更多

DPR 越高，画面越精细，但 GPU 需要渲染的像素数量也成倍增加！
:::

### 为什么需要设置像素比？

如果 Three.js 不知道你的屏幕 DPR 是 2，它只会按照 DPR = 1 来渲染。在 Retina 屏上，1 个软件像素的画布内容被拉伸到 4 个物理像素上，导致画面模糊。设置正确的像素比后，Three.js 会以更高的分辨率渲染，让画面变得清晰锐利。

### 获取设备像素比

```js
// 在浏览器控制台中输入
window.devicePixelRatio;
// 输出：1（普通屏幕）或 2（Retina）或 2.5、3 等
```

### 设置像素比

```js
renderer.setPixelRatio(window.devicePixelRatio);
```

告诉 Three.js 使用设备的实际像素比进行渲染。对于 Retina 屏幕的用户，画面会变得清晰很多。

### 为什么要限制像素比为最大 2？

```js
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
```

这是一个非常重要的性能优化！

:::caution[性能 vs 画质]

像素比越高 = 需要渲染的像素越多 = GPU 负担越重。具体来说：

| 像素比 | 每个软件像素需要渲染的物理像素 | 总渲染像素量（相对 DPR 1） |
| ------ | ------------------------------ | -------------------------- |
| 1      | 1                              | 1 倍（基准）               |
| 2      | 4（2x2）                       | **4 倍**                   |
| 3      | 9（3x3）                       | **9 倍**                   |

一台 DPR = 3 的设备，需要渲染 **9 倍于** DPR = 1 的像素量！这对 GPU 来说是巨大的负担。

更糟糕的是，**DPR 最高的设备往往是性能最弱的设备** —— 比如某些手机声称 DPR 高达 4 甚至 5。在如此小的屏幕上，人眼几乎无法分辨 DPR 2 和 DPR 5 的区别。这更多是厂商的营销噱头。

**DPR = 2 已经足够清晰了**，肉眼几乎看不到像素颗粒感。将上限限制为 2 是性能和画质之间的最佳平衡点。
:::

`Math.min(window.devicePixelRatio, 2)` 的工作原理：

| 设备 DPR | 计算过程         | 最终值 |
| -------- | ---------------- | ------ |
| 1        | Math.min(1, 2)   | 1      |
| 2        | Math.min(2, 2)   | 2      |
| 2.5      | Math.min(2.5, 2) | 2      |
| 3        | Math.min(3, 2)   | 2      |

### 为什么把 setPixelRatio 放在 resize 事件里？

除了初始化时调用一次，我们还建议在 `resize` 事件中再次调用 `setPixelRatio`：

```js
window.addEventListener("resize", () => {
  // Update sizes
  sizes.width = window.innerWidth;
  sizes.height = window.innerHeight;

  // Update camera
  camera.aspect = sizes.width / sizes.height;
  camera.updateProjectionMatrix();

  // Update renderer
  renderer.setSize(sizes.width, sizes.height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
});
```

:::note[多显示器场景]

很多人使用**双显示器**，而且两台显示器的像素比可能不同。例如，你有一台外接 1080p 显示器（DPR = 1）和一台 MacBook Pro 的内置屏幕（DPR = 2）。

当你把浏览器窗口从一台显示器拖到另一台时：

1. 窗口大小会改变 → 触发 `resize` 事件
2. `window.devicePixelRatio` 的值也会变化 → 反映新显示器的像素比

所以在 `resize` 回调中重新检测和设置像素比，可以确保窗口移动到不同显示器后仍然获得正确的渲染质量。
:::

## 步骤五：全屏模式

全屏模式是沉浸式体验的重要组成部分。想象你在玩一个 3D 游戏 —— 你肯定希望游戏能铺满整个屏幕，没有地址栏、没有标签栏、没有任何干扰。

### 双击切换全屏

我们通过监听浏览器的 `dblclick`（双击）事件来触发全屏切换：

```js
window.addEventListener("dblclick", () => {
  // 双击时的处理逻辑
});
```

### 判断当前是否全屏

在切换之前，我们需要知道当前是否已经处于全屏状态：

```js
const fullscreenElement = document.fullscreenElement || document.webkitFullscreenElement;
```

- **`document.fullscreenElement`** — 如果当前有元素处于全屏状态，返回该元素；否则返回 `null`
- **`document.webkitFullscreenElement`** — Safari 的兼容版本（下面会详细讲）

### 进入和退出全屏

```js
if (!fullscreenElement) {
  // 当前不是全屏 → 进入全屏
  if (canvas.requestFullscreen) {
    canvas.requestFullscreen();
  } else if (canvas.webkitRequestFullscreen) {
    canvas.webkitRequestFullscreen();
  }
} else {
  // 当前已全屏 → 退出全屏
  if (document.exitFullscreen) {
    document.exitFullscreen();
  } else if (document.webkitExitFullscreen) {
    document.webkitExitFullscreen();
  }
}
```

关键点：

1. **进入全屏用的是 `canvas.requestFullscreen()`** — 在你想全屏显示的**元素**上调用。你可以让页面上的任何元素全屏（视频、图片、一个 div 容器等），我们选择让画布全屏
2. **退出全屏用的是 `document.exitFullscreen()`** — 退出操作始终在 `document` 上调用，而非具体元素上
3. **用户也可以按 `Esc` 键退出全屏** — 浏览器原生支持这个快捷键

### Safari 兼容性

全屏 API 在 Safari 上的支持比较晚。为了兼容 Safari，我们需要使用带 `webkit` 前缀的版本：

| 标准版本                      | Safari 版本                         |
| ----------------------------- | ----------------------------------- |
| `document.fullscreenElement`  | `document.webkitFullscreenElement`  |
| `element.requestFullscreen()` | `element.webkitRequestFullscreen()` |
| `document.exitFullscreen()`   | `document.webkitExitFullscreen()`   |

代码中的 `if(canvas.requestFullscreen)` / `else if(canvas.webkitRequestFullscreen)` 就是用于检测浏览器支持哪个版本 —— 如果标准版本存在就用标准的，否则尝试 Safari 的版本。

:::caution[浏览器兼容性]
全屏 API 目前被所有现代浏览器支持，但在较老版本的 Safari 中需要使用 `webkit` 前缀。如果你只针对 Chrome/Firefox/Edge 开发，可以省略 `webkit` 相关代码。但为了保险起见，建议保留兼容写法。
:::

参考文档：[MDN - Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)

## 完整代码

```js
import * as THREE from "three";
import { OrbitControls } from "three/examples/jsm/controls/OrbitControls.js";

/**
 * Base
 */
// Canvas
const canvas = document.querySelector("canvas.webgl");

// Scene
const scene = new THREE.Scene();

/**
 * Object
 */
const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshBasicMaterial({ color: 0xff0000 });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

/**
 * Sizes
 */
const sizes = {
  width: window.innerWidth,
  height: window.innerHeight,
};

window.addEventListener("resize", () => {
  // Update sizes
  sizes.width = window.innerWidth;
  sizes.height = window.innerHeight;

  // Update camera
  camera.aspect = sizes.width / sizes.height;
  camera.updateProjectionMatrix();

  // Update renderer
  renderer.setSize(sizes.width, sizes.height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
});

/**
 * Fullscreen
 */
window.addEventListener("dblclick", () => {
  const fullscreenElement = document.fullscreenElement || document.webkitFullscreenElement;

  if (!fullscreenElement) {
    if (canvas.requestFullscreen) {
      canvas.requestFullscreen();
    } else if (canvas.webkitRequestFullscreen) {
      canvas.webkitRequestFullscreen();
    }
  } else {
    if (document.exitFullscreen) {
      document.exitFullscreen();
    } else if (document.webkitExitFullscreen) {
      document.webkitExitFullscreen();
    }
  }
});

/**
 * Camera
 */
// Base camera
const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height, 0.1, 100);
camera.position.z = 3;
scene.add(camera);

// Controls
const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

/**
 * Renderer
 */
const renderer = new THREE.WebGLRenderer({
  canvas: canvas,
});
renderer.setSize(sizes.width, sizes.height);
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

/**
 * Animate
 */
const clock = new THREE.Clock();

const tick = () => {
  const elapsedTime = clock.getElapsedTime();

  // Update controls
  controls.update();

  // Render
  renderer.render(scene, camera);

  // Call tick again on the next frame
  window.requestAnimationFrame(tick);
};

tick();
```

## 本课要点回顾

| 操作             | 代码                                                           | 说明                       |
| ---------------- | -------------------------------------------------------------- | -------------------------- |
| 使用视口尺寸     | `window.innerWidth` / `window.innerHeight`                     | 获取视口宽高               |
| 监听窗口变化     | `window.addEventListener('resize', ...)`                       | 窗口大小改变时触发         |
| 更新相机宽高比   | `camera.aspect = width / height`                               | 防止画面拉伸               |
| 重新计算投影矩阵 | `camera.updateProjectionMatrix()`                              | **必须调用，否则画面异常** |
| 更新渲染器尺寸   | `renderer.setSize(width, height)`                              | 让画布跟随窗口大小         |
| 设置像素比       | `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))` | 兼顾画质和性能             |
| 进入全屏         | `canvas.requestFullscreen()`                                   | 让画布全屏显示             |
| 退出全屏         | `document.exitFullscreen()`                                    | 退出全屏模式               |
