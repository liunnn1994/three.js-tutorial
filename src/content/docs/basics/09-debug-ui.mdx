## 为什么 3D 开发必须要有调试 UI

在创作任何创意项目时 -- 尤其是 3D 项目 -- 你需要频繁调整大量的参数：颜色、位置、旋转、动画速度、光照强度、物理参数等等。如果你每次调整都要修改代码、保存、等待刷新，那效率将极其低下。

调试 UI 的核心价值在于：**让你在不修改代码的情况下实时调整参数，快速找到最佳视觉效果。**

这不仅仅是为了开发者自己方便。在实际项目中，调试 UI 至少服务于三类人群：

1. **开发者**：快速尝试各种参数组合，发现意想不到的酷炫效果。课程作者坦言，他曾在项目中对所有参数都加了调试 UI，结果发现了很多"没有调试 UI 就永远找不到"的惊艳效果。
2. **设计师**：设计师通常对视觉效果有非常具体的想法，他们希望能够直接调整颜色、动画等参数，然后告诉你"就是这样，就是这个感觉"。
3. **客户**：有些客户也可以访问调试界面，自己微调效果直到满意为止。

:::tip[实际项目中的调试 UI]
在课程作者的个人作品集中，调试 UI 默认是隐藏的。用户需要在 URL 末尾加上 `#debug` 并刷新页面才能打开调试面板。通过这个面板，几乎可以调整场景中的一切 -- 太阳颜色、重力大小、动画效果等。这就是调试 UI 在实际项目中的真实用法。
:::

## lil-gui 简介

在 Three.js 生态中，常用的调试 UI 库有很多选择：

| 库名        | 特点                                            |
| ----------- | ----------------------------------------------- |
| **lil-gui** | Three.js 课程使用的库，轻量、活跃维护、API 简洁 |
| dat.GUI     | 曾经的行业标准，但已停止维护，出现安全漏洞警告  |
| Tweakpane   | 另一个优秀的调试 UI 库                          |
| Control Kit | 高性能选择                                      |
| Guify       | 轻量级选择                                      |

**我们选择 `lil-gui` 的原因：**

- 它是目前最受欢迎的选择，社区活跃
- 维护良好，有定期更新和新功能
- 使用简单，API 设计直观
- 它是 `dat.GUI` 的直接替代品 -- 只需把 `dat.gui` 替换成 `lil-gui`，代码几乎不用改动

> 官方文档：[lil-gui](https://lil-gui.georgealways.com/)
> Three.js 文档参考：[lil-gui 在 Three.js 中的使用](https://threejs.org/docs/#examples/en/libs/lil-gui/README.html)

## 安装 lil-gui

在项目目录下打开终端（如果开发服务器正在运行，先用 `Ctrl+C` 停止它），然后执行：

```bash
npm install lil-gui
```

lil-gui 是一个非常小的库，安装速度很快。安装完成后，重新启动开发服务器：

```bash
npm run dev
```

## 基本实例化

安装完成后，我们需要在代码中导入并实例化它：

```js
import GUI from "lil-gui";

const gui = new GUI();
```

**几点说明：**

- `GUI` 中的 `G` 是大写，`UI` 也是大写 -- 这是 lil-gui 文档推荐的标准写法
- 实例化后会自动在页面的右上角出现一个调试面板
- 你也可以写成 `import { GUI } from 'lil-gui'` 然后使用 `new GUI()`，效果完全一样
- 建议在代码的**最开头**就实例化 GUI，因为后面你会对场景、几何体、材质、光照等所有对象都添加控制

### GUI 配置选项

实例化 GUI 时可以传入配置对象：

```js
const gui = new GUI({
  title: "调试面板", // 自定义面板标题
  width: 300, // 面板宽度（像素），默认约 245
  closeFolders: false, // 默认是否关闭所有文件夹
});
```

- **`title`**：非常建议修改标题，这样你能清楚地区分不同的调试面板
- **`width`**：如果你喜欢给变量起比较长的名字（比如中文标签），可以适当加大宽度
- **`closeFolders`**：设为 `true` 则所有文件夹默认关闭，让页面更整洁
- 你也可以创建多个 GUI 实例来分别管理不同类别的参数

## 核心概念：只能调整对象的属性

这是 lil-gui 最重要的规则，一定要记住：

**lil-gui 只能调整对象的属性。**

`gui.add()` 方法需要两个参数：

1. **对象**（object）
2. **属性名**（property，字符串格式）

```js
gui.add(object, "property");
```

这意味着，如果你有一个独立的变量（不是某个对象的属性），你不能直接对它创建控制。你需要把它包装到一个对象中：

```js
// 不能这样做：
let myVariable = "hello";
gui.add(myVariable, "..."); // ❌ 错误！myVariable 不是对象

// 需要这样做：
const debugObject = {
  myVariable: "hello",
};
gui.add(debugObject, "myVariable"); // ✅ 正确！
```

## 控制类型详解

### 1. 数值控制（Range）

用于控制数值类型，最常用的场景是调整位置、大小、角度等。

```js
// 调整立方体的 Y 轴位置
gui
  .add(mesh.position, "y")
  .min(-3) // 最小值
  .max(3) // 最大值
  .step(0.01) // 步进值（精度）
  .name("高度"); // 显示标签
```

如果不添加 `min()`、`max()`、`step()`，GUI 会显示一个文本输入框，你需要手动输入数字 -- 这很不方便。加上这三个限制后，就会变成可以拖拽的滑块，使用体验好得多。

**两种写法对比：**

```js
// 写法一：参数写在 add() 里（不推荐，可读性差）
gui.add(mesh.position, "y", -3, 3, 0.01);

// 写法二：用链式方法调用（推荐，每个参数一目了然）
gui.add(mesh.position, "y").min(-3).max(3).step(0.01);
```

第二种写法虽然更长，但即使不看文档也能理解每个参数的含义。

### 2. 布尔值控制（Checkbox）

当属性的值是 `true` 或 `false` 时，GUI 会自动创建一个复选框。

```js
// 控制物体是否可见
gui.add(mesh, "visible").name("显示");

// 控制材质是否显示线框
gui.add(material, "wireframe").name("线框");
```

这个功能在性能调试时特别有用 -- 你可以快速切换显示/隐藏场景中的各个物体，找出哪个物体导致性能下降。

### 3. 颜色控制（Color）

颜色控制比较特殊，因为 Three.js 中的颜色不是简单的字符串或数字，而是 `Color` 类的实例。

#### 问题：为什么不能直接 `gui.add(material, 'color')`？

如果你尝试这样做，lil-gui 会尝试猜测如何处理这个属性，但会猜错 -- 因为 `material.color` 是一个 `Color` 对象，里面有很多方法和属性，lil-gui 无法将它识别为颜色。

#### 解决方案：使用 `addColor()`

```js
gui.addColor(material, "color");
```

这会弹出一个颜色选择器。

#### 色彩管理问题

即使使用了 `addColor()`，还有一个隐藏的坑：**Three.js 内部使用的颜色值和 GUI 中显示的十六进制值可能不一样**。这是因为 Three.js 使用 sRGB 色彩空间进行色彩管理（这个概念会在后面的课程详细讲解）。

如果你从 GUI 面板复制一个十六进制颜色值，然后硬编码到 `new THREE.Color('#ff6633')` 中，你会发现最终渲染的颜色和你之前在 GUI 中调出来颜色不一致。

#### 推荐做法：将颜色存储在 debugObject 中

最佳实践是把颜色存放在一个普通对象中，然后通过 `onChange` 将其同步到 Three.js：

```js
// 1. 在创建材质之前，定义颜色
const debugObject = {
  color: "#a778d8",
};

// 2. 用这个颜色创建材质
const material = new THREE.MeshBasicMaterial({ color: debugObject.color });

// 3. 添加 GUI 颜色控制，onChange 中同步到材质
gui.addColor(debugObject, "color").onChange(() => {
  material.color.set(debugObject.color);
});
```

这样做的好处：

- 颜色值只存储在一个地方，不会出现不一致
- 设计师/客户可以截图发给你颜色值，你直接用即可
- 不需要打开浏览器控制台去查找"正确的"颜色值

### 4. 函数 / 按钮控制（Button）

当你想让用户点击按钮触发某个动作时，只需在 debugObject 中添加一个函数：

```js
// 添加旋转动画按钮
debugObject.spin = () => {
  gsap.to(mesh.rotation, {
    y: mesh.rotation.y + Math.PI * 2, // 旋转一整圈
  });
};

gui.add(debugObject, "spin").name("旋转");
```

lil-gui 会检查该属性的值类型 -- 如果发现它是一个函数，就会自动创建一个按钮。点击按钮时，函数会被执行。

你可以用它来触发任何操作：重置场景、下载截图、播放动画、销毁对象等等。

### 5. 选择控制（Select）

用于在多个选项之间切换：

```js
const debugObject = {
  toneMapping: "NoToneMapping",
};

gui
  .add(debugObject, "toneMapping", [
    "NoToneMapping",
    "LinearToneMapping",
    "ReinhardToneMapping",
    "CineonToneMapping",
    "ACESFilmicToneMapping",
  ])
  .onChange(() => {
    renderer.toneMapping = THREE[debugObject.toneMapping];
  });
```

这会创建一个下拉选择框，用户可以在预定义的选项之间切换。

### 6. 文本控制（Text）

如果你只提供对象和属性名，不加 `min`/`max`/`step`，且属性是字符串类型，lil-gui 会显示一个文本输入框。

## onChange 与 onFinishChange

### onChange -- 实时触发

每次值发生变化时都会触发回调函数，包括用户正在拖拽滑块的过程中：

```js
gui.add(debugObject, "color").onChange((value) => {
  material.color.set(debugObject.color);
});
```

- 适合用于颜色、光照等需要**实时预览**的参数
- 拖拽过程中会持续触发（频率很高）

### onFinishChange -- 松手后触发

只有当用户**停止调整并松开鼠标**时才会触发回调函数：

```js
gui
  .add(debugObject, "subdivision")
  .min(1)
  .max(20)
  .step(1)
  .onFinishChange(() => {
    // 用户松手后才执行
    mesh.geometry.dispose();
    mesh.geometry = new THREE.BoxGeometry(
      1,
      1,
      1,
      debugObject.subdivision,
      debugObject.subdivision,
      debugObject.subdivision,
    );
  });
```

- 适合用于**开销较大**的操作（如重建几何体）
- 如果在 `onChange` 中重建几何体，拖拽滑块时会不断创建和销毁几何体，性能会很差

:::caution[性能警告]
构建几何体对 CPU 来说是比较耗时的操作。对于简单的立方体还好，但对于复杂几何体，在拖拽过程中不断重建会导致明显的卡顿。这就是为什么重建几何体的操作应该用 `onFinishChange` 而不是 `onChange`。
:::

## 使用文件夹组织控制项

当调试项越来越多时，使用文件夹来分类组织是非常必要的。

```js
// 创建一个文件夹
const cubeTweaks = gui.addFolder("立方体控制");

// 在文件夹中添加控制
cubeTweaks.add(mesh.position, "y", -3, 3, 0.01).name("高度");
cubeTweaks.add(mesh, "visible").name("显示");
cubeTweaks.add(material, "wireframe").name("线框");

// 文件夹可以嵌套
const materialTweaks = cubeTweaks.addFolder("材质");
materialTweaks.addColor(debugObject, "color").name("颜色");
```

**文件夹的实用技巧：**

- `cubeTweaks.close()` -- 默认关闭该文件夹
- `cubeTweaks.open()` -- 默认打开该文件夹
- 文件夹可以嵌套 -- 你可以在文件夹中再创建文件夹
- 如果你的调试 UI 变得杂乱无章，那就是你的错 -- 花点时间好好组织它们

## 动态修改几何体

这是初学者经常遇到的问题：如何通过 GUI 修改几何体的参数？

关键点在于：**几何体的构造参数（如细分段数）只在创建时使用一次**。创建完成后，改变这些参数不会自动重建几何体。你需要手动销毁旧的、创建新的。

```js
const debugObject = {
  subdivision: 2,
};

gui
  .add(debugObject, "subdivision")
  .min(1)
  .max(20)
  .step(1)
  .onFinishChange(() => {
    // 1. 先销毁旧几何体（释放 GPU 内存）
    mesh.geometry.dispose();

    // 2. 创建新几何体
    mesh.geometry = new THREE.BoxGeometry(
      1,
      1,
      1,
      debugObject.subdivision,
      debugObject.subdivision,
      debugObject.subdivision,
    );
  });
```

:::caution[内存泄漏警告]
千万不要忘记调用 `mesh.geometry.dispose()` 来销毁旧的几何体！旧的几何体会一直留在 GPU 显存中，造成内存泄漏。虽然对于简单几何体影响不大，但这是一种非常不好的编程习惯。在后续课程中会有专门讲解资源销毁（dispose）的内容。
:::

## 隐藏和显示 GUI

### hide() 和 show()

```js
gui.hide(); // 隐藏 GUI（从 DOM 中移除）
gui.show(); // 显示 GUI（重新添加到 DOM 中）
```

`hide()` 和 `close()` 的区别：

- `close()` 只是折叠面板，用户点击标题栏就能重新展开
- `hide()` 是将面板从页面中完全隐藏，用户看不到它

### 用键盘快捷键切换显示

最实用的做法是按 `H` 键来切换 GUI 的显示/隐藏：

```js
window.addEventListener("keydown", (event) => {
  if (event.key === "h") {
    gui.show(gui._hidden);
  }
});
```

`gui._hidden` 是一个内部属性，记录了 GUI 当前是否处于隐藏状态。`gui.show(true)` 会显示，`gui.show(false)` 会隐藏 -- 所以传入当前的隐藏状态就能实现切换效果。

你也可以用更直观的写法：

```js
window.addEventListener("keydown", (event) => {
  if (event.key === "h") {
    gui.domElement.style.display = gui.domElement.style.display === "none" ? "" : "none";
  }
});
```

## 在生产环境中处理调试 UI

调试 UI 只用于开发阶段，你不希望最终用户看到它。常见的处理方式：

### 方案一：通过 URL 哈希控制

```js
const urlParams = new URLSearchParams(window.location.search);
const hash = window.location.hash;

if (hash !== "#debug") {
  gui.hide();
}

window.addEventListener("keydown", (event) => {
  if (event.key === "h") {
    gui.show(gui._hidden);
  }
});
```

用户需要在 URL 后面加上 `#debug` 才能看到调试面板。

### 方案二：使用环境变量

```js
// 只在开发环境中显示
if (import.meta.env.DEV) {
  const gui = new GUI({ title: "调试面板" });
  // ... 添加各种控制
}
```

### 方案三：条件编译（Vite）

```js
// 只在开发模式下导入和创建 GUI
let gui;
if (import.meta.env.DEV) {
  const { default: GUI } = await import("lil-gui");
  gui = new GUI({ title: "调试面板" });
}
```

## 调试工作流最佳实践

### 1. 边开发边添加，不要等到最后

这是最重要的一条建议。当你添加了物理系统，就立刻加上重力的调试控制；当你添加了颜色，就立刻加上颜色的调试控制。**不要等整个项目做完了再回头添加** -- 那时你大概率不会去做了，而且会错过很多通过调试 UI 发现好效果的机会。

### 2. 使用 debugObject 集中管理参数

创建一个 `debugObject` 来存放所有需要调试的参数，而不是让它们散落在代码各处：

```js
const debugObject = {
  color: "#a778d8",
  spin: () => {
    /* ... */
  },
  subdivision: 2,
};
```

这样做的好处：

- 所有可调参数一目了然
- 不会被 Three.js 的色彩管理等机制影响
- 方便设计师/客户截图交流

### 3. 给每个控制项起有意义的名字

使用 `.name()` 方法给每个控制项添加清晰的标签：

```js
gui.add(mesh.position, "y", -3, 3, 0.01).name("立方体高度");
gui.add(mesh, "visible").name("显示立方体");
```

### 4. 善用文件夹保持整洁

随着项目增长，调试项会越来越多。用文件夹分类组织，让调试面板保持清晰：

```js
const lightFolder = gui.addFolder("光照");
const materialFolder = gui.addFolder("材质");
const animationFolder = gui.addFolder("动画");
```

### 5. 在调整完成后记录最终值

当你通过调试 UI 找到了完美的参数值，记得将最终值写回代码中，而不是一直依赖调试 UI。这样即使移除了调试 UI，效果也能保持一致。

## 完整代码示例

以下是一个整合了所有概念的完整示例：

```js
import * as THREE from "three";
import { OrbitControls } from "three/examples/jsm/controls/OrbitControls.js";
import GUI from "lil-gui";
import gsap from "gsap";

// === 调试 UI ===
const gui = new GUI({ title: "调试面板" });
const debugObject = {
  color: "#a778d8",
  spin: () => {
    gsap.to(mesh.rotation, { y: mesh.rotation.y + Math.PI * 2 });
  },
  subdivision: 2,
};

// === 场景基础 ===
const canvas = document.querySelector("canvas.webgl");
const scene = new THREE.Scene();

// === 几何体与材质 ===
const geometry = new THREE.BoxGeometry(
  1,
  1,
  1,
  debugObject.subdivision,
  debugObject.subdivision,
  debugObject.subdivision,
);
const material = new THREE.MeshBasicMaterial({ color: debugObject.color });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

// === 调试控制（使用文件夹组织） ===
const cubeFolder = gui.addFolder("立方体");
cubeFolder.add(mesh.position, "y", -3, 3, 0.01).name("高度");
cubeFolder.add(mesh, "visible").name("显示");
cubeFolder.add(material, "wireframe").name("线框");

cubeFolder
  .addColor(debugObject, "color")
  .name("颜色")
  .onChange(() => {
    material.color.set(debugObject.color);
  });

cubeFolder.add(debugObject, "spin").name("旋转");
cubeFolder
  .add(debugObject, "subdivision", 1, 20, 1)
  .name("细分")
  .onFinishChange(() => {
    mesh.geometry.dispose();
    mesh.geometry = new THREE.BoxGeometry(
      1,
      1,
      1,
      debugObject.subdivision,
      debugObject.subdivision,
      debugObject.subdivision,
    );
  });

// === 键盘快捷键 ===
window.addEventListener("keydown", (event) => {
  if (event.key === "h") {
    gui.show(gui._hidden);
  }
});

// === 渲染循环（略） ===
// ...
```
