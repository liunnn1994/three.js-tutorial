## 本课概述

在第 49 课中，我们已经在 Blender 中创建了完整的 3D 场景。现在需要做一件至关重要的事情：**把场景从 Blender 中"搬"到网页上**。

这个"搬家"过程分为三个阶段：

1. **场景优化** — 删除所有看不见的面，减少不必要的几何数据
2. **烘焙** — 把复杂的光照、阴影、颜色信息"烧录"到一张纹理图片中
3. **导出** — 将场景保存为 Three.js 可以识别的 glTF 格式

为什么这三步如此重要？因为浏览器中的实时渲染能力远不如 Blender 的离线渲染。如果我们直接把原始场景丢给浏览器，用户可能需要等待几十秒甚至几分钟才能看到画面。烘焙之后，浏览器只需要显示一张图片贴在简单的几何体上，性能会大幅提升。

## 第一部分：场景优化 — 删除多余面

### 为什么要删除面

每个 3D 物体都是由**面（Face）**组成的。面越多，GPU 需要处理的数据就越多。场景中有很多面是用户**永远看不到**的，比如：

- 物体底部（贴着地面）的面
- 两个物体交叉处被遮挡的面
- 围栏板条之间被挡住的面

删除这些面不会改变场景的外观，但能显著减少文件大小和提高渲染性能。

### 基础操作回顾

在开始之前，确保你熟悉以下 Blender 操作：

| 操作         | 快捷键 / 方法   | 说明                               |
| ------------ | --------------- | ---------------------------------- |
| 进入编辑模式 | `Tab`           | 进入物体的面/边/顶点编辑           |
| 切换选择模式 | `1` / `2` / `3` | 1 = 顶点, 2 = 边, 3 = 面           |
| 全选         | `A`             | 选中当前模式下的所有元素           |
| 反选         | `Ctrl + I`      | 取消当前选择，选中其余             |
| 删除         | `X`             | 弹出删除菜单                       |
| 隔离视图     | `/`（小键盘）   | 只显示选中的物体，隐藏其他所有物体 |
| 取消隔离     | `/`（小键盘）   | 恢复显示所有物体                   |

:::caution
`/` 键是**小键盘**上的斜杠，不是主键盘上的。如果你使用的是没有小键盘的笔记本键盘，可以通过 View 菜单中的 "Local View" 来实现相同效果。
:::

### 优化树干

树干是圆柱体，底部贴在地面上，底面的圆盘谁也看不到。

**操作步骤：**

1. 选中树干物体
2. 按 `/`（小键盘）进入隔离视图，这样你只看到这棵树
3. 按 `Tab` 进入编辑模式
4. 按 `3` 切换到面选择模式
5. 按 `Numpad 7`（底部视角）或旋转视图到树干下方
6. 点击选中树干底面的圆形面
7. 按 `X` → 选择 "Faces" 删除
8. 按 `Tab` 返回物体模式
9. 按 `/` 退出隔离视图

对场景中的**每一棵树**都重复以上操作。

### 优化原木（Logs）

原木同样是底部面不可见的物体：

1. 选中原木物体
2. 按 `/` 隔离视图
3. 按 `Tab` → `3`（面模式）
4. 旋转视角找到底部面
5. 选中并按 `X` → "Faces" 删除
6. 返回物体模式，退出隔离视图

### 优化围栏（Fences）

围栏是场景中最耗时的优化对象，原因有两个：

**难点一：板条之间的遮挡面**

围栏由多根竖直板条组成，板条之间的间隙处隐藏着连接结构（横杆）的面。这些面被板条挡住了，用户看不到，但它们仍然占据资源。

**难点二：没有使用关联副本**

如果在创建围栏时使用了关联副本（Linked Duplicate / Alt+D），修改一个围栏就能同步修改所有围栏。但本课中讲师忘记使用关联副本，所以每一段围栏都是独立物体，需要逐个修改。

**操作步骤：**

1. 选中一段围栏
2. 按 `/` 隔离视图
3. 按 `Tab` → `3`（面模式）
4. 仔细检查板条之间被遮挡的面
5. 选中这些隐藏面（可能需要旋转视角逐个确认）
6. 按 `X` → "Faces" 删除
7. 返回物体模式，退出隔离视图
8. **对每一段围栏都重复以上操作**

:::tip
如果场景中围栏段数很多，建议在以后的项目中养成使用**关联副本**（Alt+D）的习惯。这样修改一段围栏，所有关联的围栏都会同步更新，节省大量时间。
:::

### 优化石头（Rocks）

石头也有底部面需要删除。石头通常数量较多，我们可以利用集合（Collection）来批量选中它们：

**操作步骤：**

1. 在 Outliner 面板中找到包含石头的集合
2. **右键**点击该集合
3. 选择 **"Select Objects"** — 这会选中集合中的所有石头
4. 现在**所有石头都被选中**了
5. 对所有石头同时执行删除底面操作

:::note
"Select Objects" 是一个非常有用的功能。当你有大量同类物体时，把它们放在同一个集合中，然后通过右键集合来批量选中，比手动逐个点击快得多。
:::

不过注意，如果所有石头被同时选中并进入编辑模式，你需要仔细确认是否选中了所有石头（以及只选中了石头）的底面，避免误删其他面。

### 优化楼梯（Stairs）

楼梯是一个特殊的优化案例。楼梯通常由多个互相重叠的方块组成，这意味着：

- 上一个台阶的底面穿入下一个台阶的顶面
- 重叠区域内有大量看不见的面

**操作步骤：**

1. 选中楼梯物体
2. 按 `/` 隔离视图
3. 按 `Tab` → `3`（面模式）
4. 仔细检查每个台阶之间是否有重叠
5. 修复重叠问题（调整方块位置或删除重叠的面）
6. 删除所有不可见的面（台阶底部、重叠区域内部）
7. 返回物体模式，退出隔离视图

### 优化检查清单

完成所有优化后，逐一检查以下项目：

- [ ] 所有树干的底面已删除
- [ ] 所有原木的底面已删除
- [ ] 每一段围栏的遮挡面已删除
- [ ] 所有石头的底面已删除
- [ ] 楼梯的重叠面已修复并清理
- [ ] 场景在外观上没有任何可见变化

:::warning
优化时最常见的问题是**误删可见面**。每次删除后，退出编辑模式，在透视视角下旋转查看物体，确认外观没有问题。如果误删了面，按 `Ctrl + Z` 撤销。
:::

## 第二部分：解除关联副本

### 为什么需要解除关联

在 Blender 中，使用 **Alt+D**（关联副本 / Linked Duplicate）创建的物体与原始物体**共享几何数据**。这意味着它们共享同一组顶点、同一组 UV 坐标、同一组法线。

关联副本在建模阶段非常方便 -- 修改一个，所有副本同步更新。但在烘焙阶段，这会成为问题：

- **烘焙需要每个物体有自己独立的 UV 展开**
- 关联副本共享 UV 坐标，修改一个会影响所有副本
- 烘焙时不同位置的物体需要不同的光照/阴影信息

### 解除关联的操作

**操作步骤：**

1. 选中需要解除关联的物体（可以多选）
2. 按 **`F3`** 打开搜索菜单
3. 输入 **"Make Single User"**
4. 在弹出的子菜单中选择 **"Object and Data"**

```
F3 → 搜索 "Make Single User" → Object and Data
```

:::danger
在 "Make Single User" 的子菜单中，有多个选项：

- **Object and Data** — 同时解除物体和数据（几何体）的关联 ← **选这个**
- **Object and Data & Materials** — 同时解除材质关联
- **Object** — 只解除物体关联
- 只选择 "Object and Data"，**不要**选 "Materials"。因为场景中很多物体使用相同的材质，解除材质关联会导致材质数据被复制多份，增加不必要的文件体积。
  :::

### 哪些物体需要解除关联

| 情况                   | 是否需要解除关联 | 原因                     |
| ---------------------- | ---------------- | ------------------------ |
| 关联副本的树干         | 是               | 每棵树需要独立 UV        |
| 关联副本的石头         | 是               | 每块石头需要独立 UV      |
| 关联副本的围栏         | 是               | 每段围栏需要独立 UV      |
| 使用相同材质的不同物体 | 否（材质部分）   | 共享材质可以减少文件大小 |
| 独立创建的物体         | 否               | 本来就是独立的           |

## 第三部分：UV 展开

### 什么是 UV

在深入操作之前，先理解什么是 UV：

想象一个纸盒子。盒子的 3D 形状是由 6 个面组成的。如果你把盒子沿边角剪开并展平，就得到一个 2D 的平面图案。这个从 3D 到 2D 的展开过程就是 **UV 展开**。

- **U** 和 **V** 是 2D 纹理空间的坐标轴（类比 X、Y、Z 是 3D 空间的坐标轴）
- UV 展开决定了纹理图片如何"贴"到 3D 物体表面
- 每个顶点在 UV 空间中都有一个对应位置

烘焙时，渲染结果会根据 UV 坐标写入到纹理图片的对应位置。所以如果 UV 展开有问题，烘焙结果也会有问题。

### Smart UV Project（智能 UV 投影）

对于大多数物体，Smart UV Project 是最快捷的 UV 展开方式：

**操作步骤：**

1. 选中物体
2. 按 `Tab` 进入编辑模式
3. 按 `A` 全选所有面
4. 在顶部菜单选择 **UV → Smart UV Project**
5. 在弹出的对话框中调整参数（通常默认即可）
6. 点击 OK

Smart UV Project 会自动计算如何将物体的面展开到 UV 空间中。对于不规则的物体（如石头、树干），效果通常不错。

### 手动标记缝合线

对于某些复杂物体，Smart UV Project 的结果可能不理想。这时需要手动标记**缝合线（Seam）**：

缝合线告诉 Blender "沿着这条边把物体剪开"。然后 Blender 会从缝合线处将物体展开。

**操作步骤：**

1. 选中物体，进入编辑模式
2. 按 `2` 切换到边选择模式
3. 选中需要作为缝合线的边
4. 按 `Ctrl + E` → 选择 **"Mark Seam"**
5. 标记完所有缝合线后，按 `A` 全选
6. 在顶部菜单选择 **UV → Unwrap**

缝合线应该标记在**不太明显**的位置。对于圆柱体，缝合线通常放在背面。

### 检查 UV 展开质量

在 UV Editor 中检查展开结果：

| 检查项    | 正确                   | 错误                       |
| --------- | ---------------------- | -------------------------- |
| 纹理拉伸  | 方形网格看起来是正方形 | 方形网格被拉成长条         |
| UV 岛间距 | 各岛之间有足够间隙     | 岛与岛紧挨着，会渗色       |
| UV 利用率 | 大部分 UV 空间被利用   | 大片空白区域（浪费分辨率） |
| 重叠      | 没有（除非有意）       | 多个面叠在同一个位置       |

:::tip
在 UV Editor 中勾选 "Display Stretch" 可以直观地看到哪些区域有拉伸。蓝色表示正常，红色表示严重拉伸。
:::

### 对场景中所有物体执行 UV 展开

对场景中**每一个需要烘焙的物体**都执行 UV 展开：

1. 树干 → Smart UV Project
2. 原木 → Smart UV Project
3. 石头 → Smart UV Project
4. 围栏 → Smart UV Project
5. 楼梯 → Smart UV Project
6. 其他复杂物体 → Smart UV Project 或手动标记缝合线

## 第四部分：烘焙过程

### 什么是烘焙

**烘焙（Baking）** 的核心思想很简单：

> 把 Blender 中复杂的渲染结果（颜色、光照、阴影、环境遮蔽等）计算一次，然后保存为一张**纹理图片**。之后在浏览器中，只需要把这张图片贴在简单的几何体上，就能得到几乎相同的视觉效果。

打个比方：Blender 的实时渲染就像现场画一幅油画，每时每刻都在计算光影变化。烘焙就像用相机把画好的油画拍成一张照片，之后只需要展示这张照片即可。

### 烘焙前的准备

确保以下条件已满足：

- [ ] 所有需要烘焙的物体已完成 UV 展开
- [ ] 所有不可见的面已删除
- [ ] 关联副本已解除（Object and Data）
- [ ] 场景的光照已经设置好（烘焙会"拍下"当前的光照状态）
- [ ] 所有材质已正确设置

### 第一步：创建烘焙目标图像

烘焙需要一张"画布"来接收渲染结果。

**操作步骤：**

1. 将 Blender 界面切换到 **UV Editing** 工作区
2. 在左侧的 UV Editor 中，点击 **"New"** 按钮创建新图像
3. 设置图像尺寸（见下方的分辨率建议）
4. 给图像命名，例如 `baked_scene`

### 烘焙分辨率建议

| 场景规模            | 建议分辨率  | 用途             |
| ------------------- | ----------- | ---------------- |
| 简单场景 / 单个物体 | 1024 x 1024 | 小型展示项目     |
| 中等场景            | 2048 x 2048 | 本课的项目       |
| 复杂 / 高品质场景   | 4096 x 4096 | 需要高细节的场景 |

:::caution
分辨率越高，烘焙结果越精细，但文件也越大。2048x2048 是一个很好的平衡点。在浏览器中，过大的纹理会占用大量显存。
:::

### 第二步：将图像连接到材质

创建的图像需要连接到材质节点中，Blender 才知道把烘焙结果输出到哪里。

**操作步骤：**

1. 切换到 **Shading** 工作区
2. 确保选中了需要烘焙的物体
3. 在 Shader Editor 中找到该物体的材质节点
4. 添加一个 **Image Texture** 节点（`Shift + A` → Texture → Image Texture）
5. 将新创建的烘焙图像分配给这个 Image Texture 节点
6. 将 Image Texture 节点的输出连接到 Principled BSDF 节点的某个输入

### 第三步：设置烘焙参数

1. 切换到 **Render Properties**（右侧面板中的相机图标）
2. 向下滚动找到 **Bake** 面板
3. 设置以下参数：

| 参数           | 建议值                            | 说明                  |
| -------------- | --------------------------------- | --------------------- |
| Bake Type      | **Combined** 或 **Diffuse Color** | Combined 包含更多信息 |
| Width / Height | 2048 / 2048                       | 与创建的图像尺寸一致  |

### 烘焙类型选择

| 烘焙类型              | 包含内容                 | 适用场景                       |
| --------------------- | ------------------------ | ------------------------------ |
| **Diffuse Color**     | 仅颜色                   | 最简单，只保留物体本身的颜色   |
| **Ambient Occlusion** | 环境遮蔽                 | 在角落和缝隙处产生阴影效果     |
| **Shadow**            | 仅阴影                   | 只烘焙光照阴影                 |
| **Combined**          | Diffuse + AO + Shadow 等 | 本课推荐 -- 一次性包含所有信息 |

选择 **Combined** 可以在一张纹理中同时包含颜色、环境遮蔽和阴影信息，减少需要加载的纹理数量。

### 第四步：选择要烘焙的物体

烘焙前，需要选中所有参与烘焙的物体：

1. 按 `Tab` 确保所有物体都在**物体模式**
2. 按住 `Shift` 逐个点击需要烘焙的物体
3. 或者使用 `A` 全选（如果场景中所有物体都需要烘焙）

### 哪些物体不该被烘焙

:::danger
**发光物体（Emission 物体）不应该参与烘焙！**

场景中的灯具、传送门灯光等使用了 Emission（自发光）材质的物体，不应该被烘焙。原因如下：

- 发光物体使用的是**均匀的明亮颜色**（如纯白或纯黄），不需要烘焙复杂的光照信息
- 如果将发光物体一起烘焙，它们的纹理可能会被其他物体的阴影影响，变得不均匀
- 在 Three.js 中，发光物体通常需要保持独立材质，以便添加后期效果（如泛光 Bloom）

因此，在选中烘焙物体时，按住 `Shift` 点击这些发光物体来**取消选择**它们。
:::

### 第五步：执行烘焙

1. 确认所有设置无误
2. 回到 Render Properties → Bake 面板
3. 点击 **"Bake"** 按钮
4. Blender 会开始计算，进度条会显示在窗口底部

烘焙时间的长短取决于：

- 场景复杂度（面数越多越慢）
- 烘焙分辨率（分辨率越高越慢）
- 电脑性能

对于中等复杂度的场景，烘焙通常需要几十秒到几分钟。

### 第六步：保存烘焙图像

烘焙完成后，在 UV Editor 中可以看到生成的纹理图像。

**保存步骤：**

1. 在 UV Editor 中，点击 **Image 菜单** → **Save As...**
2. 选择保存位置
3. 文件名输入有意义的名称（如 `baked_scene`）
4. 文件格式选择 **JPEG**（.jpg）
5. 点击 Save

:::note
为什么选择 JPEG 而不是 PNG？因为 JPEG 的文件体积更小。烘焙的纹理不需要透明通道，所以 PNG 的无损特性在这里没有优势。JPEG 的有损压缩对烘焙纹理的质量影响微乎其微。
:::

## 第五部分：导出为 glTF

### 什么是 glTF

**glTF**（GL Transmission Format）是 3D 领域的"JPEG" -- 它是一个开放标准，专门为 Web 和移动端设计的 3D 格式。Three.js 对 glTF 的支持是最好的。

glTF 有两种主要格式：

| 格式            | 扩展名           | 特点                                               |
| --------------- | ---------------- | -------------------------------------------------- |
| **glTF Binary** | `.glb`           | 所有数据打包在一个文件中，**推荐使用**             |
| glTF            | `.gltf` + 文件夹 | 模型数据在 JSON 文件中，纹理等资源在旁边的文件夹中 |

本课使用 `.glb` 格式，因为它是一个单独的文件，方便管理。

### 导出步骤

1. 在 Blender 中，选择 **File → Export → glTF 2.0 (.glb)**
2. 在导出对话框中设置参数（见下方）
3. 选择保存位置
4. 点击 **Export glTF 2.0** 按钮

:::tip
建议将导出的 `.glb` 文件和烘焙纹理的 `.jpg` 文件放在同一个文件夹中。这样在 Three.js 中加载模型时，纹理引用路径能正确解析。
:::

### 导出参数设置

以下是本课推荐的导出参数：

| 参数                            | 设置               | 说明                                                      |
| ------------------------------- | ------------------ | --------------------------------------------------------- |
| **Format**                      | glTF Binary (.glb) | 单文件，最方便                                            |
| **Include → Transform**         | +Z Up（默认）      | 保持坐标系一致                                            |
| **Include → Limited to**        | 取消勾选           | 导出场景中所有物体（如果只想导出选中物体则勾选 Selected） |
| **Mesh → Apply Modifiers**      | **勾选**           | 确保修改器的效果被应用                                    |
| **Mesh → Compression**          | **不启用**         | 因 Blender 2.92 的 Draco 存在 bug                         |
| **Material → Export Materials** | 可选               | 如果使用烘焙纹理，可以跳过材质导出                        |
| **Transform → Forward**         | -Z Forward         | 默认，与 Three.js 一致                                    |
| **Transform → Up**              | Y Up               | 默认，与 Three.js 一致                                    |

### 关于 Apply Modifiers

在导出时勾选 **Apply Modifiers** 会将所有修改器（Mirror、Array、Subdivision 等）的效果"烧录"到最终的几何数据中。这很重要，因为：

- Three.js 不认识 Blender 的修改器
- 如果不应用修改器，导出的几何体可能是未修改的原始形状
- 应用后，导出的几何体就是最终的样子

:::caution
如果你之前已经在 Blender 中手动应用了所有修改器（Ctrl+A → Apply），那么导出时是否勾选 "Apply Modifiers" 影响不大。但**勾选它是最安全的做法**，可以确保万无一失。
:::

## 第六部分：Blender 2.92 的 Draco 压缩 Bug

### 什么是 Draco 压缩

Draco 是 Google 开发的 3D 几何体压缩库。它可以将 glTF 模型的几何数据压缩到原来的几分之一，显著减小文件体积。

### 为什么本课不使用 Draco

在本课使用的 **Blender 2.92** 版本中，导出 glTF 时的 Draco 压缩功能存在一个 **bug**：

- 启用 Draco 后导出的模型可能**无法正常显示**
- 几何数据可能会损坏或丢失
- 这不是你的操作问题，而是 Blender 该版本的已知问题

:::danger
**如果你使用的是 Blender 2.92，请不要在导出时启用 Draco mesh compression。**

如果使用较新版本的 Blender（2.93+），该 bug 已被修复，可以安全使用 Draco 压缩。使用 Draco 压缩的模型在 Three.js 中需要配合 `DRACOLoader` 加载。
:::

### 如何在不使用 Draco 的情况下减小文件体积

既然不能使用 Draco，可以通过以下方式优化文件大小：

1. **删除多余的面**（本课第一部分已完成）
2. **降低烘焙分辨率**（2048 足够，无需 4096）
3. **使用 JPEG 格式的烘焙纹理**（比 PNG 小得多）
4. **减少不必要的顶点数**

以下是本课的完整操作流程，从场景优化到最终导出：

```
场景优化
```

## 常见问题

### 烘焙结果有瑕疵怎么办

- **纹理拉伸/变形** — 检查 UV 展开，可能需要重新展开
- **颜色不正确** — 检查材质设置和灯光
- **有黑色条纹** — 可能是 UV 岛之间没有足够间距，导致纹理边缘渗色
- **部分区域很暗** — 检查是否有物体的面挡住了光照方向

### 导出后在 Three.js 中看起来不对

- **模型位置偏移** — 检查 Blender 中物体的原点位置（Origin）
- **模型大小不对** — 确认已应用缩放（Ctrl+A → Scale）
- **材质丢失** — 检查是否正确导出了材质，或烘焙纹理路径是否正确
- **法线方向反转** — 在 Blender 中选择所有面 → 法线方向朝外（Shift+N）

### UV 展开总是不理想

对于不规则的物体，试试以下方法：

1. 先手动标记关键的缝合线（`Ctrl + E` → Mark Seam）
2. 然后执行 Unwrap（不是 Smart UV Project）
3. 在 UV Editor 中手动调整 UV 岛的位置和方向
4. 重复以上步骤直到满意

:::tip
烘焙是迭代的过程。第一次烘焙的结果可能不完美，需要反复调整 UV、修改烘焙参数、重新烘焙，直到结果满意。保存多个版本的烘焙图像，方便对比。
:::
