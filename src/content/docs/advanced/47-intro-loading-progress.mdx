## 加载管理器

当你的 3D 场景包含大量资源（如 50MB 的 GLTF 模型、HDR 环境贴图等），在本地开发时加载很快，但在线上环境用户可能需要等待数秒甚至更长。如果不做任何处理，用户只会看到一个空白或闪烁的画面——这完全破坏了沉浸感。我们需要实现一个专业的加载体验：一个覆盖整个画面的加载界面，实时显示加载进度，加载完成后平滑过渡到 3D 场景。

`LoadingManager` 是实现这一目标的核心工具。它可以集中监控所有通过 Three.js Loader 加载的资源进度。

## LoadingManager 详解

### 基本用法

将 `LoadingManager` 实例传递给各个 Loader，它就会自动追踪所有加载进度：

```js
const loadingManager = new THREE.LoadingManager(
    // onLoad — 所有资源加载完成时触发
    () =>
    {
        console.log('所有资源加载完成')
        // 触发淡出动画、隐藏加载界面等
    },

    // onProgress — 每个资源加载完成时触发
    (itemUrl, itemsLoaded, itemsTotal) =>
    {
        const progress = itemsLoaded / itemsTotal
        console.log(`加载进度: ${progress * 100}%`)
        // 更新进度条
    },

    // onError — 某个资源加载失败时触发
    (url) =>
    {
        console.error('加载失败:', url)
    }
)

// 将同一个 manager 传递给所有 loader
const textureLoader = new THREE.TextureLoader(loadingManager)
const gltfLoader = new GLTFLoader(loadingManager)
const rgbeLoader = new RGBELoader(loadingManager)
```

:::tip
`onProgress` 的回调参数 `itemsLoaded` 和 `itemsTotal` 是**累计值**。如果先用 TextureLoader 加载了 5 张纹理，再用 GLTFLoader 加载了 1 个模型，total 会是 6。每次任何一个资源加载完成，`itemsLoaded` 加 1。因此进度可能不是完全线性的——一个大文件和一个小文件都只算 1 项。
:::

### 延迟渲染

在资源加载完成之前，不应该开始渲染循环，否则用户会看到不完整的场景：

```js
let sceneReady = false

loadingManager.onLoad = () =>
{
    sceneReady = true
    // 触发过渡效果
}

const tick = () =>
{
    if (sceneReady)
    {
        controls.update()
        renderer.render(scene, camera)
    }
    requestAnimationFrame(tick)
}
```

## WebGL 内覆盖层

实现"加载完成后的淡出"有多种方式。推荐将覆盖层放在 **WebGL 场景内部**而不是用 HTML 元素叠加。这样做的优势是：所有内容都在 WebGL 管线中，渲染一致性更好，也不需要处理 HTML 层和 Canvas 层的同步问题。

### 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| HTML div 覆盖在 canvas 上 | 简单易实现 | HTML 和 WebGL 分离 |
| CSS 动画 canvas 的 opacity | 较简单 | 需要协调 CSS 和 JS |
| WebGL 内的 ShaderMaterial 覆盖平面 | 完全在 WebGL 内部 | 需要写着色器，但代码量很少 |

### 使用 ShaderMaterial 创建覆盖层

思路：创建一个 2x2 的平面，使用顶点着色器让该平面**始终充满整个屏幕**（不经过模型/视图/投影矩阵变换），然后用一个 `uAlpha` uniform 控制其透明度。

```js
// 创建覆盖层
const overlayGeometry = new THREE.PlaneGeometry(2, 2)
const overlayMaterial = new THREE.ShaderMaterial({
    transparent: true,
    uniforms:
    {
        uAlpha: { value: 1.0 }
    },
    vertexShader: `
        void main()
        {
            // 直接使用 clip space 坐标，不经过任何矩阵变换
            // 这样平面始终充满整个视口（-1 到 1 的裁剪空间）
            gl_Position = vec4(position, 1.0);
        }
    `,
    fragmentShader: `
        uniform float uAlpha;
        void main()
        {
            gl_FragColor = vec4(0.0, 0.0, 0.0, uAlpha);
        }
    `
})

const overlay = new THREE.Mesh(overlayGeometry, overlayMaterial)
// 确保覆盖层始终最后渲染（在所有其他物体之上）
overlay.renderOrder = 999
scene.add(overlay)
```

:::caution
顶点着色器中直接将 `position` 作为 `gl_Position` 的 xyz 分量（补充 w=1.0），使得平面始终处于裁剪空间的 [-1, 1] 范围内，完美填满视口。这是 WebGL 中实现全屏覆盖的标准技巧——不需要任何矩阵变换，不依赖摄像机位置或 FOV。

注意：平面几何体尺寸需要是 2x2（而非 1x1），因为裁剪空间从 -1 到 1，总范围是 2。
:::

### 触发淡出

加载完成后，通过动画将 `uAlpha` 从 1 降到 0：

```js
loadingManager.onLoad = () =>
{
    // 使用 GSAP 动画（或手动 lerp）
    gsap.to(overlayMaterial.uniforms.uAlpha, {
        value: 0,
        duration: 1.5,
        ease: 'power2.inOut'
    })
}
```

如果不使用 GSAP，可以用简单的 lerp 手动实现：

```js
const tick = () =>
{
    if (sceneReady)
    {
        overlayMaterial.uniforms.uAlpha.value *= 0.95 // 指数衰减
        if (overlayMaterial.uniforms.uAlpha.value < 0.001)
        {
            overlayMaterial.uniforms.uAlpha.value = 0
        }
        controls.update()
        renderer.render(scene, camera)
    }
    requestAnimationFrame(tick)
}
```

## HTML 加载进度条

虽然覆盖层放在 WebGL 内部，但**加载进度条**使用 HTML/CSS 实现更方便（因为进度更新需要在 JavaScript 中频繁操作 DOM）。进度条在覆盖层之上、场景可见之前显示。

```html
<div id="loading-screen">
    <div class="loader">
        <div class="progress-bar" id="progress-bar"></div>
        <p id="loading-text">加载中...</p>
    </div>
</div>
<canvas class="webgl"></canvas>
```

```css
#loading-screen
{
    position: fixed;
    inset: 0;
    background: #1a1a2e;
    display: flex;
    align-items: center;
    justify-content: center;
    z-index: 100;
    transition: opacity 0.8s ease;
}

#loading-screen.loaded
{
    opacity: 0;
    pointer-events: none;
}

.progress-bar
{
    width: 200px;
    height: 3px;
    background: #e94560;
    transform: scaleX(0);
    transform-origin: left;
    transition: transform 0.3s ease;
}
```

```js
// 在 onProgress 中更新进度条
loadingManager.onProgress = (itemUrl, itemsLoaded, itemsTotal) =>
{
    const progress = itemsLoaded / itemsTotal
    const progressBar = document.getElementById('progress-bar')
    progressBar.style.transform = `scaleX(${progress})`
}

// 在 onLoad 中隐藏加载界面
loadingManager.onLoad = () =>
{
    const loadingScreen = document.getElementById('loading-screen')
    loadingScreen.classList.add('loaded')

    // 同时触发 WebGL 覆盖层淡出
    window.setTimeout(() =>
    {
        sceneReady = true
        gsap.to(overlayMaterial.uniforms.uAlpha, {
            value: 0,
            duration: 1.5
        })
    }, 500) // 等加载界面淡出后再开始 WebGL 淡出
}
```

:::tip
进度条使用 `transform: scaleX()` + `transform-origin: left` 来实现宽度变化，而不是修改 `width` 属性。`transform` 不会触发重排（reflow），性能更好。CSS 的 `transition: transform 0.3s ease` 让进度变化有平滑过渡效果。
:::

## 环境贴图预加载

环境贴图（HDR）通常需要最先加载，因为它影响所有 PBR 材质的外观。如果模型先加载完成但没有环境贴图，材质看起来会很差。可以采用串行加载策略：

```js
const rgbeLoader = new RGBELoader(loadingManager)

rgbeLoader.load('/environment.hdr', (envMap) =>
{
    scene.environment = envMap
    // 环境贴图加载完成后再加载模型
    loadModels()
})
```

:::caution
如果环境贴图和模型使用同一个 `LoadingManager`，进度条会显示两项资源的总进度。如果你希望在环境贴图加载完成后才显示进度条（或者分段显示），需要使用多个 `LoadingManager` 或手动管理加载逻辑。
:::

## 完整流程总结

1. 页面加载时显示 HTML 加载界面（覆盖全屏，z-index 最高）
2. `LoadingManager` 同时追踪所有资源（模型、纹理、环境贴图等）的加载进度
3. 每个资源加载完成时，通过 `onProgress` 更新 HTML 进度条
4. 所有资源加载完成时，`onLoad` 触发：
   - 先淡出 HTML 加载界面（CSS opacity 过渡）
   - 延迟一小段时间后，开始渲染 3D 场景并淡出 WebGL 覆盖层
5. 覆盖层完全透明后，场景完全可见，加载流程结束

:::tip
为加载界面添加一些品牌元素（Logo、品牌色进度条、加载提示文字）和微动画（脉冲动画、旋转图标等），让等待过程不那么无聊。一个小小的加载体验设计可以显著提升用户对产品质量的感知。
:::
