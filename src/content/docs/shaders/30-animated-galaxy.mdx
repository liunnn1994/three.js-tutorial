## 概述

在第 18 课中，我们用 JavaScript 实现了银河粒子系统，但遇到了性能问题——每帧更新大量粒子的 `position` attribute 会导致帧率下降。现在我们掌握了着色器知识，可以用顶点着色器在 GPU 上并行处理所有粒子的旋转动画，性能大幅提升。

:::tip
GPU 上的顶点着色器可以同时处理数十万个顶点的运算，远比 CPU 上逐个更新属性高效。使用着色器版本可以轻松支持 20 万甚至更多粒子流畅运行。
:::

## 从 PointsMaterial 到 ShaderMaterial

切换材质时需要注意几个问题：

```js
// 之前使用的 PointsMaterial
const material = new THREE.PointsMaterial({
    size: 0.02,
    sizeAttenuation: true,
    // ...
})

// 替换为 ShaderMaterial
const material = new THREE.ShaderMaterial({
    vertexShader: galaxyVertexShader,
    fragmentShader: galaxyFragmentShader,
    uniforms: {
        uTime: { value: 0 },
        uSize: { value: 30 * renderer.getPixelRatio() }
    },
    vertexColors: true,
    transparent: true,
    depthWrite: false,
    blending: THREE.AdditiveBlending
})
```

:::caution
切换到 `ShaderMaterial` 后，`size` 和 `sizeAttenuation` 属性不再可用（这些是 `PointsMaterial` 专属的）。Three.js 会在控制台发出警告。直接移除这两个属性，我们需要在着色器中自行处理粒子大小和尺寸衰减。
:::

## 自定义 Attributes

我们需要为每个粒子存储额外的数据，以自定义 attribute 的形式传入着色器：

```js
const positions = new Float32Array(parameters.count * 3)
const randomness = new Float32Array(parameters.count * 3)
const colors = new Float32Array(parameters.count * 3)
const scales = new Float32Array(parameters.count)

for (let i = 0; i < parameters.count; i++) {
    const i3 = i * 3
    const radius = Math.random() * parameters.radius
    const branchAngle = (i % parameters.branches) / parameters.branches * Math.PI * 2

    // 基础位置：在对应分支上的圆环分布
    positions[i3]     = Math.cos(branchAngle) * radius
    positions[i3 + 1] = 0
    positions[i3 + 2] = Math.sin(branchAngle) * radius

    // 随机偏移：让粒子不完全贴合分支，产生自然的弥散感
    const randomX = Math.pow(Math.random(), parameters.randomnessPower) * (Math.random() < 0.5 ? 1 : -1) * parameters.randomness * radius
    const randomY = Math.pow(Math.random(), parameters.randomnessPower) * (Math.random() < 0.5 ? 1 : -1) * parameters.randomness * radius * 0.5  // Y 方向偏移更小
    const randomZ = Math.pow(Math.random(), parameters.randomnessPower) * (Math.random() < 0.5 ? 1 : -1) * parameters.randomness * radius

    randomness[i3]     = randomX
    randomness[i3 + 1] = randomY
    randomness[i3 + 2] = randomZ

    scales[i] = Math.random()
}

geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))
geometry.setAttribute('aRandomness', new THREE.BufferAttribute(randomness, 3))
geometry.setAttribute('aScale', new THREE.BufferAttribute(scales, 1))
```

**Attribute 命名规范：**

Three.js 中使用 `ShaderMaterial` 时，`position`、`normal`、`uv`、`color` 等名称已被 Three.js 内部使用，**自定义 attribute 必须以 `a` 开头**避免冲突。因此我们使用 `aRandomness` 和 `aScale`。

:::tip
`Math.pow(Math.random(), parameters.randomnessPower)` 中，`randomnessPower > 1` 会让大部分值集中在 0 附近（粒子更靠近分支），`randomnessPower < 1` 则让值更均匀分布。Y 方向偏移乘以 0.5 让银河更"扁平"。
:::

## 顶点着色器

顶点着色器的核心任务是：根据粒子到中心的距离，计算不同的旋转速度，实现内快外慢的螺旋旋转效果。

```glsl
uniform float uTime;
uniform float uSize;
attribute vec3 aRandomness;
attribute float aScale;
varying vec3 vColor;

void main() {
    vec4 modelPosition = modelMatrix * vec4(position, 1.0);

    // === 螺旋旋转 ===
    // 计算当前粒子相对于 Y 轴的角度
    float angle = atan(modelPosition.x, modelPosition.z);

    // 计算到中心的水平距离
    float distanceToCenter = length(modelPosition.xz);

    // 距离越近，旋转越快（1.0 / distance 的关系）
    float offset = (1.0 / distanceToCenter) * uTime * 0.2;
    angle += offset;

    // 用新的角度重建 XZ 位置，Y 保持不变
    modelPosition.x = cos(angle) * distanceToCenter;
    modelPosition.z = sin(angle) * distanceToCenter;

    // === 添加随机偏移 ===
    modelPosition.xyz += aRandomness;

    // === 标准投影变换 ===
    vec4 viewPosition = viewMatrix * modelPosition;
    vec4 projectedPosition = projectionMatrix * viewPosition;
    gl_Position = projectedPosition;

    // === 粒子大小（含透视衰减） ===
    gl_PointSize = uSize * aScale * (1.0 / -viewPosition.z);

    // === 传递颜色到片元着色器 ===
    vColor = color;
}
```

**逐步解析：**

### 1. 螺旋旋转

```glsl
float angle = atan(modelPosition.x, modelPosition.z);
float distanceToCenter = length(modelPosition.xz);
float offset = (1.0 / distanceToCenter) * uTime * 0.2;
```

- `atan(x, z)` 计算粒子在 XZ 平面上的极角（注意参数顺序是 x 在前，因为我们要围绕 Y 轴旋转）
- `length(xz)` 计算粒子到中心的距离
- `1.0 / distanceToCenter` 实现差速旋转：**靠近中心的粒子旋转更快，远处的更慢**。这正是真实银河系旋臂形成的原因

### 2. 投影变换

```glsl
vec4 modelPosition = modelMatrix * vec4(position, 1.0);
vec4 viewPosition = viewMatrix * modelPosition;
gl_Position = projectionMatrix * viewPosition;
```

这是我们在前几课中学到的标准 MVP 变换链。使用 `ShaderMaterial` 时，`modelMatrix`、`viewMatrix`、`projectionMatrix` 都会被 Three.js 自动注入，无需手动声明。

### 3. 透视尺寸衰减

```glsl
gl_PointSize = uSize * aScale * (1.0 / -viewPosition.z);
```

- `uSize` — 基础粒子大小（需要乘以像素比）
- `aScale` — 每个粒子各自的随机大小缩放
- `(1.0 / -viewPosition.z)` — 视图空间中 z 坐标是负值（物体在摄像机前方），所以用负号取正。距离越远，`-viewPosition.z` 越大，粒子越小

:::caution
如果没有尺寸衰减（`1.0 / -viewPosition.z`），远处的粒子和近处的一样大，看起来不自然。这正是之前 `PointsMaterial` 的 `sizeAttenuation: true` 在背后做的事情——现在我们需要自己实现了。
:::

### 4. 颜色传递

```glsl
vColor = color;
```

`color` 是 Three.js 自动注入的 attribute，对应 `geometry.setAttribute('color', ...)` 中存储的颜色数据。通过 `varying` 传递到片元着色器。需要在材质中设置 `vertexColors: true` 才能让 Three.js 启用颜色 attribute。

## 片元着色器

片元着色器负责将方形的点精灵裁剪成圆形，并添加柔和的边缘：

```glsl
varying vec3 vColor;

void main() {
    // 计算片元到粒子中心的距离（gl_PointCoord 范围是 0.0 ~ 1.0）
    float dist = length(gl_PointCoord - vec2(0.5));

    // 丢弃超出圆形范围的片元
    if (dist > 0.5) discard;

    // 计算柔和边缘的强度
    float strength = 1.0 - (dist * 2.0);
    strength = pow(strength, 1.5);

    gl_FragColor = vec4(vColor, strength);
}
```

**`gl_PointCoord` 详解：**

- 当渲染 `THREE.Points` 时，每个点精灵（point sprite）在片元着色器中可以通过 `gl_PointCoord` 获取当前片元在点内的归一化坐标
- 坐标范围 `(0.0, 0.0)` 到 `(1.0, 1.0)`，中心点为 `(0.5, 0.5)`
- `length(gl_PointCoord - vec2(0.5))` 计算到中心的距离
- `dist > 0.5` 时 `discard` 丢弃片元，将方形裁剪为圆形
- `pow(strength, 1.5)` 让边缘衰减更柔和，产生光晕效果

:::tip
`discard` 关键字会直接丢弃当前片元，不写入颜色缓冲区。这是实现粒子透明边缘的标准做法，比设置 `alpha = 0.0` 更高效，因为可以跳过后续的混合计算。
:::

## 性能对比

| 方面 | JavaScript 版本 | 着色器版本 |
|------|----------------|-----------|
| 旋转计算 | CPU 每帧逐粒子更新 | GPU 并行处理 |
| 粒子上限 | ~5 万（开始卡顿） | 20 万+（流畅） |
| 每帧开销 | 更新 buffer + `needsUpdate` | 只更新一个 uniform（`uTime`） |
| 数据传输 | CPU -> GPU 每帧传输 | 初始传输一次，之后 GPU 自行计算 |

:::tip
着色器版本的核心优势：每帧只需要更新 `uTime` 这一个 `float` 值（4 字节），而不是更新 20 万个粒子的位置数据（20 万 * 3 * 4 字节 = 2.4MB）。这在数据传输量上有几个数量级的差异。
:::
